# Техническое задание: Arabica AI Pro 1.0

**Версия документа:** 1.0, 2026-10-08. **Статус:** к реализации. **Приоритет:** собственное офлайн-приложение для качественного двустороннего перевода русский ↔ современный стандартный арабский (MSA, фусха), не Google Translate и не диалектный переводчик.

## 1. Принципиальные ограничения

1. **Полный офлайн:** исходная машина Windows 10 x64 не подключалась и не будет подключаться к интернету. Программа работает без учётной записи, API-ключей, активации, обновлений, телеметрии, доступа к CDN, winget, pip, git, Hugging Face и установке драйверов из сети.
2. **Доставка:** единственный доступный способ — скачать все файлы с iPhone, перенести через флешку/Lightning-USB-адаптер, запустить `setup.exe`. Не требовать у пользователя скачивать модели отдельно и не предлагать командную строку для установки.
3. **Железо:** Windows 10 x64 (версия сборки пока неизвестна), 40 ГБ ОЗУ, 30–100 ГБ свободного пространства, CPU/GPU неизвестны. Базовый режим **CPU-only** обязателен; совместимость с конкретными инструкциями CPU устанавливать диагностикой до сборки. GPU лишь дополнительная оптимизация.
4. **Языки:** только русский и современный стандартный литературный арабский. Входные тексты на диалектах не нормализовать тайно: сообщить, что диалекты не поддерживаются; возможен осторожный литературный эквивалент только после явного выбора.
5. **Модель:** никакие модели Google; никакой Google Translate, TranslateGemma или облачных моделей во время выполнения. Допустима открытая базовая модель с соблюдением лицензии — продукт собственной разработки, но не «обученная с нуля» нейросеть.
6. **Результат:** только собранный, реально протестированный офлайн-установщик с включёнными модельными весами, движком, бинарными зависимостями, лицензиями, хешами и инструкцией; один прототип GUI или HTML нельзя считать релизом.

## 2. Утверждённая архитектура

```text
PySide6 / Qt Desktop (Windows 10, x64)
  ├─ TranslationEditor (двухпанельный интерфейс, RTL/LTR)
  ├─ DictionaryView / ContextExplorer / Terminology
  ├─ OfflineTranslatorService
  │    ├─ segmenter + document-context manager
  │    ├─ terminology injection + protected spans
  │    ├─ model-inference adapter (llama.cpp, локальный GGUF)
  │    ├─ deterministic structural checks
  │    └─ optional second pass for flagged segments
  ├─ SQLite: история, избранное, личный глоссарий, версии правок
  └─ Export: TXT, DOCX (локально)
```

**Выбор реализации v1:** Python + PySide6 (поддержка Windows 10 1809+) + `llama.cpp` в нативном CPU-сборочном комплекте, с инкапсулированным адаптером. Прямой встроенный вызов через библиотеку предпочтителен для исключения сетевых разрешений; если надёжнее отдельный локальный процесс, разрешён только `127.0.0.1` без внешнего bind, без HTTP на внешние адреса, без браузера; проверить брандмауэр и отсутствие внешней сетевой активности. Путь установки/выполнения на кириллице должен поддерживаться.

**Упаковка:** PyInstaller **onedir** или эквивалент с включёнными Qt, Python, бинарниками, VC runtime, моделью GGUF, настройками; затем Inno Setup с `DiskSpanning=yes` и `DiskSliceSize=1800000000`, чтобы каждая часть была менее 2 GiB (лимит GitHub Release на один asset). Полностью автономный setup из `setup.exe` и `setup-*.bin`. Не включать неизвестные неиспользуемые модели в конечный продукт. Повреждение частей должно приводить к понятной ошибке.

**Никакой обязательной WebView2, Docker, WSL, Visual Studio, CUDA или Python на пользовательском ПК.** Отсутствие аппаратного ускорителя не является отказом в запуске. При CPU без AVX2 предусмотреть совместимый бинарник либо честно зафиксировать проверяемое минимальное требование после диагностики; нельзя отправить бинарник с ошибкой illegal instruction.

## 3. Модель и стратегия выбора

- **Принятый стартовый кандидат для v1:** Qwen3.5-9B, текстовая GGUF-квантизация **Q6_K**, приблизительно **7.4 GB** (фактический размер зафиксировать из выбранного репозитория и SHA-256). Исходная модель Apache-2.0; квантованную версию и корректность её авторства/лицензии проверить отдельно. Модель изначально универсальная — нет гарантий превосходства над коммерческими переводчиками.
- **Соперник для проверки:** официальный Qwen3-14B-GGUF Q5_K_M (приблизительно 10–11 GB). Тестировать на одинаковом наборе RU↔MSA с теми же правилами перевода, отключённой сетью и одинаковой метрикой. При значительном качественном выигрыше рассмотреть 14B, если CPU скорость приемлема; в дистрибутив включать **одну** выбранную модель.
- **Ограничения:** неизвестны CPU, GPU и точная версия Windows; цифры скорости и максимальная длина перевода не гарантированы. На первом запуске определять CPU-возможности, память и безопасные значения потоков/контекста. Цель памяти: пиковая RAM ≤30 ГБ, без свопинга, при обычных текстах. Пробовать 4096–8192 контекстных токенов, адаптировать до измерений на реальном ПК.
- В Qwen3.5 режимы рассуждения управляются шаблоном. Не полагаться на `/nothink` (официально не поддерживается); если отключение нужно, использовать поддерживаемое `chat_template_kwargs.enable_thinking=False` при корректной интеграции либо проверенный эквивалент для выбранного llama.cpp. Для пользовательского ответа не показывать внутренние рассуждения.
- **Важно:** обучение модели с нуля не входит в 1.0. LoRA/дообучение — отдельный проект с юридически пригодными параллельными корпусами, раздельными train/validation/test и реальным улучшением на закрытом тесте.

## 4. Переводческий функционал

**Перевод RU→MSA и MSA→RU:** слова; короткие фразы; абзацы; длинные тексты с предварительной сегментацией. Сохранять логическую связность и одинаковые именования между сегментами. Максимальную длину определять по безопасному контекстному окну; большие тексты разбивать без потери абзацев и помечать неоднозначности.

**Режимы:**
- Точный: максимальная семантическая точность; запрет домыслов и вставок, сохранять числа, собственные имена, отрицания и модальность.
- Литературный: естественные формулировки на целевом языке с сохранением значения и регистра; без добавления фактов.
- Профессиональный: политическая, дипломатическая, военная, научная и официально-деловая терминология; глоссарий обладает приоритетом, но пользователь видит конфликт терминов.

**Словарная карточка слова:** лемма, часть речи (только когда уверены), несколько значений с маркировкой контекста, примеры, морфология при доступности, альтернативные переводы; предупреждать о неоднозначности. Не выдавать неуверенные грамматические факты как проверенные.

**Вспомогательные инструменты:** огласовка и транскрипция кириллицей **по явному запросу**; отделять их от основного текста перевода, сохранять точность огласовок под тестами. Возможность вставить контекст в отдельное поле; обратный просмотр оригинал↔перевод по абзацам; копирование, история, избранное и редактируемый словарь. Никаких диалектных словарей.

**Сохранение смысла и постпроверки:** детерминированно проверять соответствие чисел, дат, имён, сокращений, единиц измерения, символов, отрицания (с эвристическими пометками, не автокорректировать), количество абзацев, сохранение ссылок/маркированных элементов. Ошибки подсвечивать и давать повторно перевести отдельный сегмент. Не подменять исходное содержание.

**Документы:** TXT и DOCX импорты/экспорты, сохранять абзацы и базовое форматирование; сложные таблицы, рисунки и колонтитулы — либо отдельный явно протестированный scope, либо отмеченная «не поддерживается» возможность. PDF/OCR в 1.0 не включать, чтобы не создавать ложных ожиданий.

## 5. UI/UX

- Русскоязычный интерфейс; две синхронизированные панели; определение направления только вручную/с возможностью исправить; переключение RU↔MSA одним действием.
- Установить для арабской панели Qt `RightToLeft`, а для русской `LeftToRight`; правильные bidi marks; правильное перемещение курсора, выделение, копирование и кавычки.
- Большой шрифт для арабского, статус «модель загружается», «перевод», индикатор процесса, отмена перевода, отсутствие фриза GUI.
- Статусы ошибок простым русским: файл модели не найден/повреждён, нет памяти, несовместимая инструкция процессора, недостаточно места, неверные части установщика.
- Личные данные только локально в `%LOCALAPPDATA%/ArabicaAIPro`; экспорт/очистка истории, без аналитики и удалённых логов.

## 6. Качество, испытания, приёмка

**Лингвистические:** двухсторонний закрытый тест с 400+ парами предложений (общеупотребительные, политика, дипломатия, военные, научные, художественные, многозначные слова, отрицания, имена, даты, числительные). FLORES-200/PLUS допустим как одна часть оценки с соблюдением условий доступа/лицензий; экспертная проверка и уникальные собственные кейсы обязательны. Метрики chrF++/COMET (если лицензии/среда позволяют), анализ серьёзных ошибок, ручной слепой рейтинг 1–5. Сравнение с доступным эталоном Google/другими моделями проводить на стороне разработчика, НЕ внутри конечного приложения.

**Технические:** тест на чистой Windows 10 x64 1809+ и отключённом физическом сетевом адаптере; нет попыток скачать что-либо, всё запускается без прав администратора после установки при соответствующем сценарии, перевод реального текста завершён. Проверить cold-start, RAM peak, токены/сек, отсутствие GUI-фризов, unicode-RTL, экспорт, долгие тексты, отмену, перезапуск, работу в кириллическом пути, удаление. Протоколы теста в release.

**Критерии релиза:** 0 блокирующих ошибок; ≥99% системных/integration тестов проходят (100% обязательных критических), нет критических необнаруженных изменений чисел/отрицания в утверждённом тестовом наборе; живой перевод RU↔MSA работает без сети; задокументированы реальные ограничения скорости и качества; размеры частей ≤1.8GB в десятичной системе (каждый строго менее 2 GiB), SHA-256 каждой части + модели + манифест, журналы/скриншоты smoke-тестов, исходники и лицензии.

**Не заявлять** «лучше Google» без статистически проверяемого независимого сравнения. Не выдавать макет за конечную сборку. Не обещать точность 100%.

## 7. Разработка и передача

### Этап A. Discovery
Проверка лицензии/архитектуры/CPU-совместимости, протоколы сравнения моделей, набор тестов. Claude выполняет разработку и переводческую инженерию; Astra выполняет независимый технический аудит. Краткие ADR для спорных решений.

### Этап B. MVP
GUI + реальный GGUF backend + перевод двух направлений + локальный глоссарий + детерминированные проверки; без сети. Провести интеграционные тесты.

### Этап C. Pro
Импорт/экспорт DOCX, текстовые сегменты с контекстом, огласовки/транскрипция по запросу, улучшенный UI, история, объяснение переводческих решений.

### Этап D. Windows release
Claude: CI Windows x64, pinned dependencies + binary hashes, frozen onedir build, автономный Inno setup, split slices, SHA-256, сторонние лицензии; аппаратно изолированный e2e-smoke. Публикация полного набора частей в Release. Релиз не выпускать до зелёной приёмки.

## 8. Передача с iPhone

- Сборщик публикует `setup.exe`, `setup-1.bin`, ... вместе с `SHA256SUMS.txt`, `INSTALL_OFFLINE_RU.txt` и `manifest.json`. Все установочные части находятся в одной папке.
- На iPhone скачать каждый файл в «Файлы», скопировать на exFAT-флешку через совместимый Lightning-USB адаптер (при необходимости с питанием).
- На Windows запустить `setup.exe` с флешки либо скопировать все части в одну папку, выбрать путь установки (предупредить о свободном месте), далее использовать без интернета.
- Для безопасности устройство с интернетом не должно менять историю на офлайн-компьютере. Проверка хеш-сумм встроенной утилитой PowerShell `Get-FileHash` по желанию и в руководстве; приложение само валидирует модель при первом запуске.
- Запас свободного места: целиться в 20–25GB для установки/временных файлов, но определять точный объём автоматически в релизе. Предупреждать, если реального свободного места меньше необходимого.

## 9. Что не входит в 1.0

Веб-версия, Android/iOS-приложение, распознавание речи, произношение аудио, OCR/PDF, машинное обучение с нуля, диалекты, работа по сети, автоматическое получение обновлений, доступ к Google API, перевод иных языков.
