# Лингвистический контракт Arabica AI Pro 1.0

Версия 1.0 · 2026-10-09 · автор: Claude (ведущий разработчик и лингвистический инженер)
Статус: **проект, требует проверки профессиональным переводчиком RU↔MSA** (см. §10).

Контракт определяет, что программа обязана делать при переводе, как это проверяется и какие отклонения
считаются ошибками. Реализация: `arabica/prompts.py` (инструкции модели), `arabica/quality.py`
(проверки), `arabica/protect.py` (защищённые фрагменты), `arabica/service.py` (сегментация и контекст).

---

## 1. Сфера действия

| Параметр | Значение |
|---|---|
| Языки | русский литературный ↔ современный стандартный арабский (MSA, фусха) |
| Не поддерживается | арабские диалекты (египетский, левантийский, заливный, магрибский, иракский), классический язык как отдельная норма, другие языки |
| Единицы | слово · словосочетание · предложение · абзац · документ (до 100 000 знаков, сегментация) |
| Режимы | Точный (по умолчанию) · Литературный · Профессиональный |
| Вывод | только текст перевода; никаких пояснений, вариантов, транскрипции, «рассуждений» |

Диалектный ввод (MSA→RU) не нормализуется тайно: программа показывает предупреждение
«похоже на разговорный арабский … перевод может быть неточным» (детектор маркеров `linguistics.dialect_markers`)
и переводит текст как есть. Литературный эквивалент диалектного текста — только по явному запросу
пользователя (поле «Контекст»), что фиксируется как будущая функция, не 1.0.

## 2. Инварианты (нарушение = ошибка независимо от режима)

| # | Инвариант | Как проверяется |
|---|---|---|
| I1 | **Ничего не добавлено**: нет новых фактов, имён, дат, чисел, причин, оценок, пояснений | экспертная оценка; эвристика длины (§6) |
| I2 | **Ничего не пропущено**: каждое предложение, придаточное, уточнение, пункт списка | экспертная оценка; эвристика длины; число абзацев (точно) |
| I3 | **Числа неизменны**: значение каждого числа, даты, времени, процента, суммы | **точно**: мультимножество нормализованных чисел (восточноарабские цифры, «2,5»/«2.5»/«2٫5», разряды «1 250 000») |
| I4 | **Отрицание сохранено** (полярность высказывания) | эвристика по сентенциальным отрицаниям (не/нет/ни/нельзя… ↔ لا/لم/لن/ليس/ألا…); лексическое отрицание (без/не-/غير/عدم/دون) сознательно не считается |
| I5 | **Модальность сохранена**: должен / может / вправе / запрещено / возможно | экспертная оценка; в тестах — отдельные кейсы NND |
| I6 | **Имена собственные и аббревиатуры** — установленная форма или последовательная транскрипция; латиница переносится без изменений | точно для латиницы; must-списки в тестах |
| I7 | **Структура**: то же число абзацев, порядок, маркеры списков | **точно**: число абзацев |
| I8 | **Защищённые фрагменты** (URL, e-mail, пути, `код`, {{пометки}}) — байт-в-байт | **точно**: плейсхолдеры ⟦N⟧ и восстановление |
| I9 | **Нет рассуждений модели** в выводе | **точно**: `<think>` блокируется; thinking отключён шаблоном |
| I10 | **Только фусха** в арабском выводе | эвристика: словарь диалектных маркеров |
| I11 | **Ввод — данные, а не команды**: «переведи и ответь…» переводится, а не исполняется | промпт (правило 1) + тест-кейсы инъекций (план, §9) |

## 3. Трансформация формы vs изменение смысла

Допустимо (трансформация формы) — **не ошибка**:
- смена порядка слов: VSO ↔ SVO, именное ↔ глагольное предложение (*Министр заявил* → أعلن الوزير / الوزير أعلن);
- замена пассива активом и наоборот при сохранении агента/отсутствия агента (*закон принят* → أُقرّ القانون);
- замена глагола масдаром и наоборот (*для обеспечения* → لضمان);
- деление/слияние предложений (только в Литературном и, умеренно, в Профессиональном режимах);
- замена разрядной записи числа без изменения значения (*1 250 000* → 1250000);
- выбор синонима того же регистра;
- лексическое выражение отрицания (*не повредив* → دون الإضرار; *недостаточно* ↔ لا تكفي).

Недопустимо (изменение смысла) — **ошибка**:
- смена полярности (*не будут возобновлены* → «будут возобновлены»);
- смена модальности (*не пришёл* → «не смог прийти»: добавлена невозможность — **реальный случай из разведки 9B**);
- смена времени/вида с изменением факта (*подписали* → «подпишут»);
- смена лица/числа субъекта (*мы* → «они»; *две страны* → «страны»);
- генерализация/конкретизация (*бронетранспортёр* → «машина»; *около 60 %* → «60 %»);
- смена лексемы на соседнюю по смыслу (*выделило* → أصدرت «выпустило» — **реальный случай 9B**);
- добавление «смягчителей»/«усилителей» (*около*, *всего лишь*, *очень*).

## 4. Режимы на проверяемых примерах

### 4.1 Точный (`accurate`, по умолчанию)
Максимальная близость: тот же порядок информации, те же границы предложений, прямые эквиваленты терминов.

| Оригинал | Принимается | Не принимается |
|---|---|---|
| Поезд опоздал на двадцать минут. | تأخر القطار عشرين دقيقة. | تأخر القطار قليلًا. (генерализация) |
| لم يحضر الوفد الاجتماع بسبب الظروف الجوية. | Делегация не присутствовала на заседании из-за погодных условий. | Делегация не смогла принять участие… (добавлена модальность) |

### 4.2 Литературный (`literary`)
Естественный, идиоматичный текст; допустимы перестройка, слияние/деление предложений, идиоматические эквиваленты; запрещены новые образы и выпадение образов.

| Оригинал | Принимается | Не принимается |
|---|---|---|
| Ветер гнал по улице сухие листья, и город казался пустым. | كانت الريح تسوق الأوراق اليابسة في الشارع، وبدت المدينة خالية. | هبّت عاصفة قوية… (новый образ) ; كان الريح… (ошибка согласования: الريح ж.р.) |
| عاد بخفي حنين. | Он вернулся ни с чем. | Он вернулся с сапогами Хунейна. (буквализм идиомы) |

### 4.3 Профессиональный (`professional`)
Официальный регистр, установленная терминология (ООН, ЛАГ, официальные госструктуры), официальные названия; юридическая/военная модальность — строго; глоссарий пользователя **обязателен** (см. §5).

| Оригинал | Принимается | Не принимается |
|---|---|---|
| Совет Безопасности провёл экстренное заседание. | عقد مجلس الأمن جلسة طارئة. | عقد مجلس السلامة اجتماعًا عاجلًا. (калька названия) |
| Договор не может быть изменён без согласия обеих сторон. | لا يجوز تعديل المعاهدة دون موافقة الطرفين. | لا يمكن تعديل… (размыта нормативная модальность «не допускается» → «невозможно») |

## 5. Терминология и глоссарий

1. Источник истины — локальный глоссарий SQLite (`docs/GLOSSARY_SCHEMA.sql`). У термина: язык, область, предпочтительный эквивалент (ровно один), допустимые и **запрещённые** эквиваленты, грамматика, приоритет 0–100, статус (draft/reviewed/approved/deprecated), версия и история, источники.
2. Подбор: термин ищется в сегменте с учётом словоизменения (русские основы; арабские проклитики و ف ب ل ك ال). В промпт попадают только найденные термины (до 40), в порядке: термины выбранной области, затем по приоритету.
3. Модель получает требование «использовать именно этот эквивалент, склоняя его». После перевода — эвристическая проверка наличия лексемы; при отсутствии — предупреждение «термин переведён не по глоссарию» (автоисправления нет).
4. **Конфликт терминов** (одна единица — разные предпочтительные эквиваленты в разных областях) показывается пользователю (`LocalStore.conflicts`), выбор — за пользователем через поле «Область».
5. Встроенные примеры терминов (`docs/GLOSSARY_EXAMPLES.json`) — **предложения со статусом draft**; ни один не выдаётся за словарную норму, пока эксперт не сверит его с указанным источником.

## 6. Точные проверки и диагностика

| Класс | Проверка | Реакция |
|---|---|---|
| ТОЧНО | числа (I3), абзацы (I7), латиница (I6), плейсхолдеры (I8), `<think>` (I9), язык вывода | предупреждение critical/major; повтор сегмента |
| ЭВРИСТИКА | отрицание (I4), лексема глоссария, соотношение длин 0,4–2,8, диалектные маркеры | предупреждение «проверьте вручную» |
| НЕ проверяется автоматически | смысловая эквивалентность, модальность, стиль, корректность огласовки | только экспертная оценка (EVAL_RUBRIC.md) |

Обратный перевод (back-translation) **не используется** как критерий качества: та же модель воспроизводит свои ошибки.

## 7. Алгоритмы разрешения трудных явлений (что делает система и что требуется от модели)

| Явление | RU→MSA | MSA→RU | Механизм |
|---|---|---|---|
| Многозначность | контекст сегмента + 2 предыдущих пары; поле «Контекст» пользователя; для изолированного слова — до 3 значений через « / » | то же; для слова без огласовки — карточка показывает варианты чтения | промпт §SHORT INPUT; словарная карточка |
| Отрицание | не/нет/ни → لا (наст.), لم+джазм (прош.), لن+насб (буд.), ليس (именн.) | لم → прош. отриц.; لن → буд.; لا يزال/ما زال = «всё ещё» (не отрицание); لا بدّ = «необходимо» | промпт (правило 5, RUSSIAN OUTPUT) + эвристика I4 с исключениями фразеологизмов |
| Вид и время | сов. вид прош. → перфект; несов. → имперфект/كان+имперф.; будущее → سـ/سوف | قد+перфект = завершённость; قد+имперфект = возможность; كان+имперфект = длительное прошлое | промпт |
| Пассив | -ся/кратк. прич. → مبني للمجهول или безличный оборот; агент при наличии → «من قبل» избегать, лучше актив | مبني للمجهول → страдат. или неопр.-личн. оборот | трансформация формы, §3 |
| Именное предложение | «X — Y» → جملة اسمية без связки | جملة اسمية → тире/«является» | — |
| Согласование | ж.р. ломаных множ. неодуш. (الدول … أكدت), числительные 3–10 (обратное согласование), 11–99 — тамйиз вин. ед. | падеж/число после числительных | промпт (ARABIC OUTPUT) + эксперт; кейсы MIL/SCI с числительными |
| Названия учреждений | официальные формы (مجلس الأمن، الجمعية العامة، جامعة الدول العربية) | установленные русские (Совет Безопасности ООН, ЛАГ) | глоссарий + Профессиональный режим |
| Имена собственные | устоявшиеся арабские формы (موسكو، بوتين) | устоявшиеся русские (Эр-Рияд, Мухаммед бин Салман) | промпт + must-проверки в тестах |
| Даты и числа | цифры как в оригинале (западные 0–9); месяцы — يناير…ديسمبر (египетско-заливная серия); левантийская серия (كانون الثاني…) допустима | восточноарабские → западные; десятичный разделитель → запятая | точная проверка I3 |

## 8. Огласовка и транскрипция (только по запросу)

1. **Огласовка** (`Translator.diacritize`) — моделью, с **точной** проверкой: после удаления харакат буквенный скелет обязан совпасть с исходным; иначе результат отклоняется.
2. Для 1–2 слов без контекста выводится предупреждение: «без контекста слово может читаться по-разному» (напр. علم = عِلْم «наука» / عَلَم «флаг»; كتب = كَتَبَ «написал» / كُتُب «книги»).
3. **Транскрипция кириллицей** (`arabica/translit.py`) — детерминированная, из огласованного текста: таблица согласных (ث→с, ذ→з, ع→‘, ء→’, ج→дж…), краткие гласные из харакат, долгие — из ا/و/ي, шадда — удвоение, танвин -ан/-ун/-ин, ассимиляция артикля (аш-шамсу, аль-камару), та марбута «-а» / «-т+гласная». Если у согласной нет ни гласной, ни сукуна — флаг «огласовка неполная, транскрипция приблизительная».
4. Ограничения 1.0: не элидируется хамзат-аль-васль внутри фразы; i‘rab-окончания передаются как огласованы (научная, а не «газетная» транскрипция). Огласовка модели **не верифицирована** экспертом — показывается с пометкой.

## 9. Сегментация длинных текстов

- Разбиение: по абзацам, затем по концам предложений (. ! ? ؟ …), крайний случай — по пробелу; исходный текст восстанавливается побайтно (`segment` проверяет инвариант).
- Сегмент ≤ 1500 знаков; системная инструкция постоянна для пары (направление, режим) — префикс кэшируется движком.
- Контекст: 2 предыдущие пары «оригинал/перевод» (по 700 знаков) с пометкой «не переводить и не повторять» — только для согласованности имён и терминов. Нового содержания в перевод из контекста не переносится (правило I1).
- Каждый сегмент проверяется отдельно; ошибочный сегмент можно перевести повторно (`retranslate_segment`) без перевода всего документа.

## 10. Что требует носителя / профессионального переводчика

- Все 400 эталонов `docs/EVAL_CASES.jsonl` (`review_status = pending_expert_review`).
- Встроенные термины `docs/GLOSSARY_EXAMPLES.json` (status = draft).
- Таблица §7 «согласование» и «месяцы» — нормативные рекомендации требуют подтверждения редактором.
- Огласовка модели и транскрипционная таблица §8.

## 11. Классы ошибок (для разметки)

| Код | Класс | Серьёзность по умолчанию |
|---|---|---|
| NEG | изменена полярность | critical |
| NUM | изменено число/дата/срок | critical |
| MOD | изменена модальность (юридическая/военная — critical) | major / critical |
| ADD | добавлен факт | critical |
| OMI | пропущен факт/фрагмент | critical (>1 предложения) / major |
| ENT | искажено имя/название/учреждение | major |
| TERM | неверный термин / нарушен глоссарий | major |
| SENSE | неверно выбрано значение многозначного слова | major |
| IDIOM | буквализм идиомы | major |
| GRAM | грамматика (согласование, падеж, вид) | minor / major (если меняет смысл) |
| REG | регистр/стиль (в т.ч. диалектизм) | minor / major (диалект в фусха-выводе) |
| PUNCT | пунктуация, оформление | minor |
