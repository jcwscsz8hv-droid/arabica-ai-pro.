# Рубрика оценки и процедура выбора модели

Версия 1.0 · 2026-10-09. Связанные файлы: `docs/EVAL_CASES.jsonl` (400 кейсов), `tools/ci/bench.py`
(прогон через реальный конвейер программы), `tools/ci/bench_report.py` (автоматика + слепой лист),
`docs/LINGUISTIC_CONTRACT.md` §11 (классы ошибок).

## 1. Набор данных

| | RU→MSA | MSA→RU |
|---|---|---|
| Общеупотребительные | 50 | 50 |
| Официально-политические | 30 | 30 |
| Дипломатические | 20 | 20 |
| Военные | 20 | 20 |
| Научно-технические | 20 | 20 |
| Литературные | 20 | 20 |
| Многозначность / идиомы | 20 | 20 |
| Отрицания / числа / даты / имена | 20 | 20 |
| **Итого** (уровни 1/2/3) | **200** (62/78/60) | **200** (62/78/60) |

- Все исходные тексты — **авторские** (написаны для проекта, CC0); арабские исходники MSA→RU написаны отдельно, а не получены обратным переводом русского набора.
- Эталоны написаны Claude и **не являются независимой экспертизой** (`review_status = pending_expert_review`). До проверки профессиональным переводчиком chrF++ против них — ориентир, а не мера качества.
- Набор — **закрытый тест**: `split = closed_test_do_not_train`; `source_sha1` позволяет исключить кейсы из любого будущего обучающего корпуса. Промпты не настраиваются по ошибкам на этом наборе; для настройки нужен отдельный dev-набор.
- Автоматические проверки каждого кейса выводятся из **исходника** (числа, наличие отрицания, `must_contain`, «короткий ввод»). Скрипт сборки сверяет их и с эталоном — так найдены и исправлены ошибки разбора чисел с арабскими проклитиками (و9، الـ14) и размечены случаи лексического отрицания.

## 2. Автоматические метрики (вспомогательные)

1. **chrF++** (`sacrebleu 2.4.3`, `CHRF(word_order=2)`, корпусной уровень) по направлению и категории.
2. **Детерминированные флаги** на кейс: `numbers`, `negation`, `must_contain`, `wrong_language`, `reasoning_leak`, `dialect`, `length_ratio`, `no_output`. Флаг — повод для проверки, не доказанная ошибка.
3. **Производительность**: p50/p95 секунд на кейс, холодный старт, пиковая RSS — с указанием процессора хоста.
4. COMET в 1.0 не используется (требует загрузки отдельной модели и проверки её лицензии); может быть добавлен на стороне разработчика.

## 3. Слепая экспертная оценка

Лист `blind_sheet.csv` (генерируется отчётом): переводы систем перемешаны и подписаны A/B; ключ `blind_key.json` оценщикам не выдаётся.

| Поле | Шкала | Определение |
|---|---|---|
| Адекватность | 1–5 | 5 — смысл передан полностью; 4 — мелкая неточность без искажения; 3 — заметная неточность, суть сохранена; 2 — серьёзное искажение части; 1 — смысл не передан / противоположный |
| Естественность | 1–5 | 5 — как написал бы носитель (фусха / литературный русский); 1 — неграмотно или непонятно |
| Терминология | 1–5 или н/п | соответствие установленной терминологии и официальным названиям |
| Худшая ошибка | none / minor / major / critical | по классам §11 контракта |
| Типы ошибок | NEG, NUM, MOD, ADD, OMI, ENT, TERM, SENSE, IDIOM, GRAM, REG, PUNCT | можно несколько |
| Пропуски/добавления | да/нет | отдельная отметка I1/I2 |

Процедура:
- минимум **2 эксперта** на кейсах уровня 3 и на кейсах, где у любой системы сработал автоматический флаг; расхождение ≥ 2 баллов или в «худшей ошибке» — арбитраж **третьим** экспертом;
- оценщики видят исходник и эталон и знают, что эталон — лишь один из допустимых вариантов;
- согласованность: доля совпадений «худшей ошибки» и взвешенная κ по адекватности; при κ < 0,4 — повторная калибровка на 20 кейсах.

## 4. Критические ошибки (вето)

critical = NEG, NUM, ADD/OMI факта, MOD в юридическом/военном тексте, искажение имени/учреждения с подменой референта. Система со значимо большим числом critical (точный тест Мак-Немара на парах кейсов, α = 0,05) **не выбирается**, независимо от средних баллов (BENCHMARK_PLAN §4).

## 5. Процедура выбора: Qwen3.5-9B Q6_K vs Qwen3-14B Q5_K_M

1. Один набор, одна версия промптов (`PROMPT_VERSION`), одна сборка llama.cpp (`tools/ci/pins.json`), температура 0, thinking отключён шаблоном каждого кандидата.
2. Режим по категории: литературные → `literary`; официально-политические, дипломатические, военные, научные → `professional`; остальные → `accurate`.
3. Автоматический отчёт публикуется в `ci-reports/bench/…/BENCHMARK_AUTO.md`. **Победитель по автоматике не объявляется.**
4. После слепой оценки: 50 % экспертная точность и critical-ошибки + 20 % качество языка + 15 % терминология и связность + 10 % скорость + 5 % ресурсы/надёжность. Вето §4 — до взвешивания.
5. Если экспертов к сборке нет: выбирается модель с меньшим числом **детерминированных** critical-флагов (numbers / negation / must_contain / no_output), при равенстве — более быстрая. Решение фиксируется в ADR как **временное**, а `KNOWN_LIMITATIONS.md` прямо сообщает, что экспертная оценка не проведена.

## 6. Что запрещено

- Заявлять «лучше Google» или «точность 100 %».
- Использовать обратный перевод как единственный критерий.
- Настраивать промпты по ошибкам закрытого набора и отчитываться на нём же.
- Выдавать скорость, измеренную на CI, за скорость на ПК пользователя.
